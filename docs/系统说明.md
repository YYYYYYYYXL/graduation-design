# 系统需求与实现说明

## 页面与模型

普通页面提供上传、去噪、前后图片与下载，默认 `restormer_sidd_batch16`。实验页面提供六个独立选项：DnCNN DIV2K、DnCNN SIDD、Restormer DIV2K、Restormer SIDD、P2N、BM3D。五个网络使用现有权重直接推理，BM3D 使用现有实现，无训练入口。

实验页面分带噪照片与清晰照片两种输入。带噪照片可附配对干净参考图；清晰照片生成固定种子的高斯噪声，原图作为参考。结果展示输入基线、指标汇总、各输出、同位置局部放大、CSV 和每项 JSON。模型名称与路径来自 `models.json`，缺失文件对应的选项不在前端显示，不用随机权重替代。

原任务进度文件及接口保持原样。模型训练记录仍从本地 CSV 读取。页面不显示训练日志或模型来源，文件改动不触发服务器部署。

## 模块

- `web/index.html`、`app.js`、`style.css`：表单、多模型串行请求、表格、局部放大与导出，无构建流程。
- `app.py`：上传解码、方向修正、缩小、统一 RGB、加噪、调用模型、计算指标、保存结果。
- `inference.py`：严格加载现有网络或调用 BM3D，缓存一个网络，记录参数量、文件大小和用时。
- `denoising_metrics.py`：现有 RGB PSNR 与 SSIM 实现。
- `image_quality.py`：无参考 BRISQUE 和小波噪声估计，评分文件位于 `third_party/brisque/`。
- `models.json`：六项配置。DnCNN 在实际推理时按权重保存格式选择匹配的现有网络，不写死 SIDD 的保存格式。页面名称不包含 batch、云端或待提供权重；修改配置后需重启服务。
- `results/web/`：每项请求独立目录，不覆盖历史结果，不自动清理。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| GET `/` | 页面 |
| GET `/api/settings` | 默认模型、最大像素和上传大小 |
| GET `/api/models` | 模型配置与是否存在，不加载网络 |
| GET `/api/history/<model_id>` | 已有日志，缺失返回空列表 |
| GET `/api/progress` | 原任务进度 |
| POST `/api/denoise` | 上传并进行一次推理 |
| GET `/results/<run_id>/<filename>` | 允许的 PNG、CSV、JSON 文件 |

`POST /api/denoise` 使用 multipart 表单。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| image | 必填 | 输入；synthetic=true 时为清晰图 |
| model | restormer_sidd_batch16 | 注册表内模型 ID |
| reference | 无 | 同场景、同尺寸、已对齐的干净图；合成模式不能提供 |
| experiment | false | true 且无参考图时计算无参考评分 |
| device | auto | auto / cpu / cuda；BM3D 固定 CPU |
| sigma | 空 | 0～255；BM3D 空时从输入估计，合成噪声必填 |
| synthetic | false | true 时添加固定种子高斯噪声 |
| seed | 42 | 0～4294967295 的整数，仅合成时参与加噪 |

响应包含模型、UTC 时间、原图/处理尺寸、缩小标记、设备、实际与请求 σ、合成标记与种子、是否分块、三个时间字段、参数量、权重字节数、输入/输出指标、指标模式、输入/参考像素 SHA-256 和下载 URL。摘要仅用于保证同组输入一致，不检查权重来源。

`metrics` 和 `input_metrics` 含 `psnr`、`ssim`、`brisque`、`estimated_noise`、`quality_notes`。有参考图时仅算 PSNR/SSIM，无参考实验时算 BRISQUE/噪声估计；普通去噪无参考时不评分。`metric_mode` 为 reference / no_reference / none。未测量值为 null，PSNR 完全相同为字符串 `∞`，非有限评分不输出为数字。CSV 包含输入基线字段与失败评分说明；前端整组 CSV 的第一行数据是输入基线。

时间字段 `seconds` 为算法去噪用时，`load_seconds` 为模型加载调用用时，`total_seconds` 为服务端处理用时。参数量 `parameters` 从实际加载网络统计，BM3D 为 null；`weights_bytes` 为权重文件字节数，BM3D 为 0。

错误状态为 400 参数或图片错误、404 未知记录、409 去噪忙、413 上传过大、500 依赖/加载/执行错误。完整异常只写服务日志。评分无效返回空值与说明，保留有效去噪结果。

## 对比口径

1. 单次上传合计最多 50 MB，支持 PNG/JPEG/WebP/BMP/HEIC/HEIF；原图每边至少 11 像素、总像素不超过 1 亿。转正后，大于 400 万像素等比例缩小，输出为 8-bit RGB。
2. 参考图检查转正后的原始尺寸，与输入用相同缩小规则；内容是否对齐需用户保证，系统不做配准。参考图不进入去噪网络。
3. 各项请求使用同一上传文件、同一参考图及同一加噪种子。前端锁定输入，核对返回的尺寸和像素摘要，不合并输入不一致的结果。一项失败不阻止后续项。
4. PSNR/SSIM 使用输出 PNG 像素与干净参考计算。无参考指标使用相同处理尺寸，不为评分再次缩放。局部放大只改变显示，不重新算指标。
5. BRISQUE 使用 OpenCV 4.11.0 的 LIVE-R2 评分文件与亮度图，0～100，越低通常越好。它不是还原准确率，不能单独判定细节恢复是否正确。亮度恒定图不打分；边长小于 32 像素不算无参考指标。来源与引用见 `third_party/brisque/README.md`。
6. 噪声估计采用逐 RGB 通道小波估计均值，换算到 0～255 尺度。图像纹理、过度平滑会影响数值，仅为辅助。
7. 神经网络采用 256×256 核心块、32 像素边界，记录是否分块；BM3D 整图运行。P2N 只直接推理，不更新参数。
8. 神经网络计时包含分块、设备传输和量化，BM3D 计时包含噪声估计和去噪；总处理时间还包含读写、加载与评分，不包含上传、浏览器显示及最终记录写入。冷热加载、CPU/GPU、分辨率及线程差异需随结果说明。
9. 网络参数量、权重文件大小不等于实测运行内存。单图表现不代表整体模型质量，不自动合成总分或评定冠军。同架构两个数据集版本也可能有训练设置差异，不能只归因于数据集。

单机服务同一时间只执行一项任务，关闭页面不取消已经提交的请求。结果保存到本地，无数据库需求。依赖/配置修改后需重启服务；本地修改不影响独立部署的线上环境。
