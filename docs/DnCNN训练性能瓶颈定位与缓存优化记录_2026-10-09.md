# DnCNN 训练性能瓶颈定位与缓存优化记录

> **项目名称：** 基于深度学习的图像去噪平台设计与实现  
> **记录日期：** 2026-10-09  
> **涉及模块：** SIDD 数据读取与预处理、PyTorch DataLoader、DnCNN 训练与验证  
> **结论：** 完整 Epoch 由最初约 **22 分钟**缩短至 **31.77 秒**，按两次实测约数计算，整体耗时减少约 **97.6%**，速度约为原来的 **41.5 倍**。

## 1. 最初的问题：GPU 在等 CPU

项目使用 RTX 4050 Laptop GPU（6GB 显存）训练 20 层 DnCNN。SIDD 训练集共有 **222 对原图**，每对每轮生成 **4 对 128×128 Patch**，每轮共 **888 个 Patch、111 个 Batch**（实际 Batch Size 为 8）。

第一次完整训练耗时约 **22 分钟/Epoch**，但监控中 GPU 利用率经常只有 **1%**，计算功耗约 **14～15W**，CPU 使用率却较高。虽然 CUDA 已正常使用，GPU 却没有持续处于计算状态。

**最初的核心问题不是模型计算慢，而是模型等待下一批训练数据。**

## 2. 怎样定位到真正的耗时环节

### 2.1 分开测数据准备与模型计算

对若干 Batch 分别计时（剔除首批初始化开销）：

| 环节 | 平均耗时/Batch |
|---|---:|
| DataLoader 数据准备 | **15.80 秒** |
| GPU 传输、前向传播、反向传播及参数更新 | **0.15 秒** |

数据准备约占测得时间的 **99%**。这说明单纯优化卷积网络或升级显卡，不是当前最有效的办法。

### 2.2 检查 `sidd_dataset.py` 源代码

原始 Dataset 每次 `__getitem__()` 都重新打开一对高分辨率 NOISY/GT PNG，使用 Pillow 完整解码后，才裁剪出一个 **128×128** Patch。每张原图一轮采样 4 次，相当于**同一对大图被重复解码约 4 次**。随机打乱又让这些重复访问分散在不同 Batch 中，难以复用已解码的数据。

### 2.3 用独立计时确认 PNG 解码是主因

对 **100 对原始图像**执行读取、解码、裁剪、增强、转换与传输的分段计时：

| 操作 | 累计耗时 | 占各环节测得总时间 |
|---|---:|---:|
| 磁盘读取压缩文件 | 5.91 秒 | 4.1% |
| **PNG 解码** | **139.31 秒** | **95.5%** |
| 随机裁剪 + 数据增强 | 0.08 秒 | 约 0.1% |
| Tensor 转换 + Batch 组装 + GPU 传输 | 0.56 秒 | 约 0.4% |

本次测试程序总耗时约 **147 秒**。由此确认：**瓶颈主要在 CPU 对高分辨率 PNG 的完整解码，而不是 SSD 读取、裁剪、增强或 GPU 运算。** 把裁剪转移到 GPU 预计收益很小。

## 3. 优化过程及实测变化

### 阶段一：增加并行读取，但未解决重复解码

将 DataLoader 从 `num_workers=0` 改为 **2**，启用预取与常驻 Worker。数据加载平均耗时从 **15.80 秒/Batch**下降到约 **6.76 秒/Batch**；说明并行有帮助，但两个 Worker 仍然在重复解码大 PNG。

### 阶段二：按原图分组生成 Patch

调整采样逻辑：**每对原图只解码一次，立即连续裁剪 4 对随机 Patch**，而不是每取一个 Patch 就解码一次。两个 Worker 并行准备数据，每次把 2 组 × 4 个 Patch 组成 8 个训练样本。

- 连续读取 12 个 Batch 的测试：总计 **34.79 秒**，平均 **2.90 秒/Batch**。
- 接入正式训练后，完整 Epoch 从约 **22 分钟**下降到约 **5 分钟**。

这一改动验证了“减少重复解码”比“单纯增加 Worker”更有效，但每个 Epoch 仍需要重新解码全部训练原图。

### 阶段三：提出两种彻底避开重复解码的缓存方案

| 对比维度 | **方案 A：完整解码图像缓存** | **方案 B：预生成 Patch 缓存** |
|---|---|---|
| 缓存内容 | 完整 RGB 图像保存为未压缩 `.npy`（uint8） | 每对原图预生成 32 对 128×128 Patch，保存为未压缩 `.npy`（uint8） |
| 每轮采样 | 从完整像素数组**动态随机裁剪**4 对 Patch | 从预先生成的 32 对候选中抽 4 对 |
| 是否再次 PNG 解码 | 否 | 否 |
| 随机裁剪位置 | 每轮可重新选择 | 受固定候选库限制 |
| 训练时主要开销 | 内存映射访问 + 裁剪 + 增强 | 读取候选 Patch + 增强 |
| 缓存空间 | 约 **17,351 MiB** | 约 **666 MiB** |

还考虑过将裁剪和增强移至 GPU，但分段计时显示这些操作几乎不耗时，因此**没有采用 GPU 预处理方案**。

### 阶段四：A/B 性能对照实验

两方案都使用 SIDD 训练集 **222 对原图**、每轮 **888 个 Patch**、实际 Batch Size **8**、**2 个 Worker**、相同的 DnCNN 结构与训练步骤，各跑 **2 个 Epoch**；比较缓存体积、数据等待时间、GPU 计算时间和整轮纯训练耗时。

两份缓存同时生成的**一次性预处理**总耗时约 **399 秒**，其中 PNG 解码约 **374 秒**。这个时间是生成两套缓存的总成本，不能分别算给 A 和 B。

| 指标 | 方案 A：完整缓存 | 方案 B：Patch 缓存 |
|---|---:|---:|
| 缓存体积 | **17,350.7 MiB** | **666.0 MiB** |
| 第 1 个 Epoch（含初始化） | 28.37 秒 | 22.29 秒 |
| 第 2 个 Epoch（预热后） | **14.88 秒** | **14.86 秒** |
| 第 2 轮等待数据 | **0.19 秒** | **0.11 秒** |
| 第 2 轮模型训练计算 | 14.66 秒 | 14.72 秒 |

**结果：两方案预热后的纯训练速度几乎相同，差距仅 0.02 秒，没有实际判别价值。** 这次对照不含验证阶段；首轮还受 Worker 启动、操作系统文件缓存等因素影响。

### 最终选择：方案 A

选择 **完整图像 `.npy` 缓存 + 内存映射读取 + CPU 动态随机裁剪与增强**，原因如下：

1. **几乎与方案 B 一样快**：预热后数据等待不到 0.2 秒/Epoch，GPU 基本不再因数据加载停顿。
2. **保留原有训练策略**：每轮都能在整张图上重新随机裁剪，而不是局限于预生成的 32 个位置；更适合后续持续训练。该数据多样性优势属于方案设计特性，尚不能等同于“PSNR 一定更高”。
3. **改动集中、可兼容断点**：模型结构、NOISY/GT 配对关系、训练划分与实际 Batch 大小均保持不变，可从已有权重继续训练。

代价是约 **17GB** 的磁盘占用；如果以后磁盘空间不足，方案 B 仍是可用替代方案。

## 4. 接入正式训练后，发现验证集仍在重复解码

将方案 A 接入 `sidd_grouped_dataset.py` 后，从已完成的第 2 个 Epoch 断点继续训练：

- **Epoch 3：完整耗时 98.89 秒**；Val PSNR **29.70 dB**。
- 训练阶段已明显加速，但验证阶段仍通过原来的 `SIDDDataset(split="val")`，每轮读取并完整解码 **46 对 PNG**，再进行固定中心裁剪。

因此又做了最后一步优化：

1. **一次性**使用原验证逻辑，对 46 对 NOISY/GT 图像进行 **256×256 固定中心裁剪**。
2. 保存为未压缩 `uint8 .npy` 缓存，约 **17 MiB**，之后不再重复解码验证集 PNG。
3. 在 `sidd_dataset.py` 中让 `split="val"` 优先读取对应缓存；保持验证样本、裁剪范围和 PSNR 计算规则不变。
4. 测试缓存读取与 Tensor 维度正常后，从第 3 个 Epoch 断点继续。

**Epoch 4：完整耗时仅 31.77 秒**，Val PSNR **30.15 dB**。此次“完整 Epoch”已包括训练、验证与保存权重，因而可以与最初约 22 分钟的完整训练流程做总体对比。

## 5. 总体优化效果

| 阶段 | 主要变化 | 实测完整 Epoch 耗时 |
|---|---|---:|
| 初始版本 | 每个 Patch 重复读取并解码原始 PNG，单进程加载 | **约 22 分钟** |
| 分组采样版本 | 每对原图只解码一次生成 4 个 Patch，2 个 Worker | **约 5 分钟** |
| 正式使用方案 A | 训练集改为完整 `.npy` 缓存；验证集仍读 PNG | **98.89 秒** |
| 最终优化版本 | 训练集完整缓存 + 验证集固定 Patch 缓存 | **31.77 秒** |

**总耗时：约 1320 秒 → 31.77 秒；减少约 97.6%，整体提速约 41.5 倍。** 由于初始耗时是约数、不同轮次存在缓存预热影响，这属于真实训练过程的阶段性对比，而非严格隔离变量的基准测试。

模型在优化期间正常续训：验证集 PSNR 从第 1 轮 **28.98 dB** 逐步达到第 4 轮 **30.15 dB**，超过同一验证集原始 NOISY 的 **29.33 dB**。这一改善主要体现训练继续推进，**不能直接归因于数据缓存**。

## 6. 经验总结

- **不要把“GPU 利用率低”直接判断为显卡或 CUDA 故障。** 先拆分计时：数据准备、GPU 计算、验证、保存。
- **找到真正耗时的操作再优化。** 本次读取、裁剪、增强都不慢，95.5% 的数据处理时间花在 PNG 解码上。
- **先减少重复工作，再考虑并行。** 双 Worker 能缓解等待；避免每轮反复解码才能从根本上提速。
- **性能与训练质量都要顾及。** 在速度几乎相同的情况下，优先保留完整图像的动态随机裁剪能力。
- **训练集快了还不够，验证集也会成为新瓶颈。** 最终把固定验证内容预处理并缓存，才将完整 Epoch 压缩到约半分钟。

> **最终方案：** 原始 SIDD PNG 保留不动；训练集使用完整解码 `.npy` 缓存，CPU 每轮动态随机裁剪/增强；验证集使用固定中心裁剪 `.npy` 缓存；DataLoader 并行预取；GPU 专注 DnCNN 训练与验证。
