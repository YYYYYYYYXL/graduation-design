# DnCNN 训练耗时异常与数据加载优化记录

**项目：** 基于深度学习的图像去噪平台设计与实现  
**日期：** 2026-10-08  
**涉及模块：** SIDD 数据加载、DnCNN 训练  
**结论：** 首轮训练耗时长的主要原因不是显卡算力不足，而是原始图像反复读取、解码，使 GPU 长时间等待数据。

## 一、问题现象

首次使用 SIDD 数据集训练 DnCNN，**1 个 Epoch 约需 22 分钟**。训练期间 GPU 利用率长期很低，CPU 较忙，显卡没有表现出持续高负载的状态。

起初怀疑模型没有正确调用 GPU，但分段计时表明：**每个 Batch 的数据准备约需十几秒，而 GPU 完成训练计算只需约 0.15 秒**。绝大部分时间消耗在数据加载，而非卷积运算。

## 二、根本原因

原版 `sidd_dataset.py` 的 `__getitem__()` 每取一个训练 Patch，就重新打开并解码一对高分辨率的 **NOISY / GT PNG**，随后才随机裁剪为 `128×128`。

由于每张原图每轮采样 4 个 Patch，**同一对大图在一个 Epoch 中被重复读取、解码约 4 次**。实际上 GPU 只需要小尺寸 Patch，却反复等待 CPU 处理整张大图。

原训练 `DataLoader` 还设置了 `num_workers=0`，数据准备与模型计算串行进行，等待更加明显。

## 三、解决方法

1. 新增分组采样版 `SIDDGroupedDataset`：**一对原图只解码一次，连续随机生成 4 对对齐 Patch**，保留原有随机裁剪、翻转和旋转。
2. 将训练 `DataLoader` 调整为 **2 个 Worker 并行加载与预取**，降低 GPU 等待时间。
3. 每批读取 2 对原图，各生成 4 个 Patch；整理后仍以 **8 个 Patch/Batch** 输入原 DnCNN，不改变网络结构、数据集划分和每轮训练 Patch 总数。

## 四、为什么耗时下降这么多

这次并不是让 GPU 本身变快，而是**大幅减少了 GPU 等待数据的时间**：

- **优化前：** 读取大 PNG → 解码 → 裁出 1 个 Patch；同一原图重复做多次。
- **优化后：** 读取大 PNG → 解码一次 → 裁出 4 个随机 Patch；同时由两个进程准备后续数据。

原来几乎全部训练时间都堵在图像解码环节；消除重复工作后，GPU 能更频繁地拿到数据执行计算，所以整轮训练耗时显著下降。

## 五、优化效果

| 对比项目 | 优化前 | 优化后 |
|---|---|---|
| 单个 Batch 的数据加载 | 约 16 秒 | 约 3 秒（短程测试） |
| 完整 1 个 Epoch（含验证） | **约 22 分钟** | **约 5 分钟** |
| 网络结构及训练 Patch 数量 | 不变 | 不变 |

**整体训练速度约提升 4 倍多，单轮节省约 17 分钟。** 优化后的第 2 个 Epoch 已成功完成，模型正常验证并保存权重。

> 注：验证集仍沿用原始逐图解码方式，因此每轮训练结束后的验证阶段仍有一定等待时间；分组采样也改变了 Batch 的样本组合，后续仍需持续观察模型验证指标。

## 六、最终结论

**训练耗时跨度大的核心原因是数据处理效率，而不是 DnCNN 计算量或显卡性能。** 通过检查 Dataset 源码、分开测量数据加载与 GPU 计算、减少重复 PNG 解码并并行准备数据，成功将单轮训练从约 22 分钟压缩至约 5 分钟。
